OP/ED discovery & detection

Conceptual step-by-step reference for the per-title opening/ending detector (src-tauri/src/op_ed.rs). This is separate from library filename scanning (scanner.rs / rescan_library).

Operation tags

Steps below are tagged when they touch disk or spawn external tools:

Disk read Disk write SQLite ffmpeg ffprobe fpcalc In-memory only

What we are trying to find

For one anime title with multiple episode files, find audio segments that repeat across episodes (typical OP ~90s near the start, ED ~90s near the end), build a template fingerprint from the best candidate, then locate that template in every episode with conservative matching so false skips are rare.

Results are stored in SQLite (op_ed_templates, episode_op_ed_segments, anime.no_op_ed). Raw Chromaprint vectors are cached on disk under data/op-ed/fingerprints/*.fp.

How the user triggers work (jobs)

  1. “Fingerprint audio” (optional pre-pass) Enqueues one op_ed_chroma job per episode (resource type chroma, staggered ≥1s apart on HDD). Each job calls run_episode_chroma_fingerprint → full-episode fingerprint cache only. SQLite list episodes. Disk read/write .fp cache. ffprobe if duration missing in DB. ffmpeg + fpcalc per uncached range.
  2. “Detect OP/ED” Enqueues op_ed_detect (identity op_ed_detect:{anime_id}, resource type none; ffmpeg/fpcalc run only in prerequisite chroma jobs). Before starting, the job manager enqueues any missing chroma jobs and sets them as prerequisites so detection reuses full-episode fingerprints when chroma jobs finish first. SQLite Disk cache check per episode.
  3. Worker thread run_op_ed_detect_job runs on spawn_blocking. SQLite access is kept to brief with_conn bursts; ffmpeg/ffprobe/fpcalc never run while holding the DB mutex.

Core building block: one audio fingerprint

Almost every step eventually calls ensure_episode_fingerprint(path, start_sec, duration_sec):

  1. Resolve video path normalized_video_path — canonical path must exist. Disk read stat + canonicalize.
  2. Cache key cp{ANALYSIS_VERSION}_{file_hash}_{start_ms}_{duration_ms} where file_hash comes from path + size + mtime. Disk read metadata for hash.
  3. Cache hit If data/op-ed/fingerprints/{key}.fp exists, load signed Chromaprint integers from the binary file and return. Disk read In-memory only thereafter.
  4. Cache miss — decode audio extract_pcm_range runs ffmpeg: -ss start -t duration -i video -vn -ac 1 -ar 11025 -f s16le (stdout PCM). ffmpeg Disk read source video file.
  5. Cache miss — fingerprint PCM pcm_to_chromaprint writes a temporary .s16le under the fingerprint cache dir, runs fpcalc -raw -json -signed …, deletes the temp file, parses JSON fingerprint array. Disk write temp raw (deleted immediately after). fpcalc
  6. Persist cache Save frame count + little-endian i32 values to {key}.fp. Disk write

Duration lookup: If episodes.duration_seconds in SQLite is already > 0, ffprobe is skipped. Otherwise probe_duration runs ffprobe on the file. ffprobe Disk read

Detect job — initialization

  1. Load episodes Non-missing episodes for the anime, ordered by episode number then path. SQLite read
  2. Reset title flags Set no_op_ed = 0, op_ed_analysis_version = ANALYSIS_VERSION. SQLite write
  3. Ensure segment rows exist Insert episode_op_ed_segments with status pending for OP and ED if missing (preserves prior terminal rows on re-run). SQLite write
  4. Run OP, then ED run_kind_detection is called twice (OP block index 0, ED block index 0). Progress steps are precomputed from episode count.

Phase A — Discovery (discover_repeated_seed)

Goal: find a 15-second audio window that appears on multiple episodes before building the 90s template.

  1. Seed pool Take up to the first MAX_SEED_EPISODES (10) episodes. Need at least 2 episodes or discovery is skipped. In-memory only
  2. Per seed episode — choose search region
    • OP: from t=0, length = min(duration, 180s).
    • ED: last min(duration, 180s) of file.
    Duration from DB or ffprobe. Skip episode if region < 20s (15s window + 5s margin).
  3. Slide 15s windows Within the region, extract fingerprints every 7.5s (half of SEED_WINDOW_SEC): offsets 0, 7.5, 15, … while offset + 15 ≤ extract_len. Each window → ensure_episode_fingerprint(path, start+offset, 15) (cache / ffmpeg / fpcalc as above). Collect SeedCandidate entries.
  4. Cluster by cross-episode similarity For each candidate window A, compare to every other window B on a different episode. Use segment_fingerprint_similarity (average per-frame Hamming similarity on Chromaprint subfingerprints). In-memory only
  5. Pick best cluster Keep the seed whose cluster has the most distinct episode IDs with similarity ≥ SEED_MATCH_THRESHOLD (0.82). Need cluster size ≥ 2 or discovery fails. In-memory only

Discovery does not write templates yet; it only returns the winning seed’s episode id, start time, and the list of supporting episode ids.

Phase B — Build template

  1. If discovery failed Mark all non-terminal segments not_found (search_pass seed). If the title has ≥ 3 episodes, set anime.no_op_ed = 1. SQLite write
  2. Extract 90s template fingerprint From the seed episode at seed.start_sec, duration SEGMENT_DURATION_SEC via ensure_episode_fingerprint. Disk ffmpeg fpcalc on cache miss.
  3. Insert template row op_ed_templates stores kind (op/ed), start, duration 90s, confidence 1.0, fingerprint cache key, JSON list of source episode ids. SQLite write

Phase C — Per-episode matching

For each episode (skipping rows already in a terminal status: matched / not_found / skipped):

  1. Status → analyzing Link segment to template id, search_pass initially optimistic. SQLite write
  2. Load full-episode candidate fingerprint Fingerprint from t=0 for max(duration, 91s) so the template can slide anywhere needed. Reuses chroma pre-cache when the key matches the full-episode chroma job. Disk ffmpeg fpcalc on miss.
  3. Optimistic search pass Slide the 90s template across candidate frames only inside:
    • OP: first 180s (in frames).
    • ED: last 180s.
    For each offset, compute sliding average similarity; track best offset; then run match_quality_at_offset (average, strong-frame ratio, lower quartile). Accept only if all three thresholds pass. In-memory only
  4. Full search pass (fallback) If optimistic pass finds nothing, repeat sliding match over the entire episode duration. search_pass → full. In-memory only
  5. Record result
    • Matched: store start/end seconds, confidence, template id, candidate fp key.
    • Not found: increment fail streak; after 3 consecutive failures on titles with ≥3 episodes, stop processing further episodes for this kind.
    SQLite write

Detect job — completion

  1. After both OP and ED Set anime.op_ed_analyzed_at = CURRENT_TIMESTAMP. SQLite write
  2. Playback (separate from detection) When settings.skip_op_ed is on, the player listens to mpv://time-pos and seeks past segments with status matched. No ffmpeg during skip; reads segment times from SQLite / in-memory player state.

End-to-end flow (one kind: OP or ED)

User: Detect OP/ED → Job queue (optional chroma prerequisites per episode) → run_op_ed_detect_job → load episodes [SQLite] → discover_repeated_seed → for ≤10 episodes × sliding 15s windows in OP/ED region → ensure_fingerprint [disk cache | ffmpeg + fpcalc] → cluster windows across episodes [memory] → if cluster found: → build 90s template fingerprint [disk | ffmpeg | fpcalc] → insert op_ed_templates [SQLite] → for each episode: → full-episode candidate fp [disk | ffmpeg | fpcalc] → match in optimistic window [memory] → else match full timeline [memory] → upsert episode_op_ed_segments [SQLite] → else: not_found + maybe no_op_ed [SQLite] → op_ed_analyzed_at [SQLite]

Reset OP/ED analysis (title settings)

  1. Delete segment rows and templates for the anime. SQLite write
  2. Remove fingerprint files referenced in DB, then scan data/op-ed/fingerprints/ and delete any .fp whose key stem matches any episode path hash for that title (catches orphans). Disk read directory listing. Disk write deletes.

Similarity math (in-memory)

  • Each Chromaprint “frame” is a signed 32-bit subfingerprint; frame period ≈ 0.1238s.
  • Frame similarity = 1 − (popcount(a XOR b) / 32).
  • Segment similarity = mean over aligned frames.
  • Template match slides template across candidate; best offset must pass average, strong-frame ratio, and lower-quartile gates.
In-memory only — no disk or subprocess during comparison.
